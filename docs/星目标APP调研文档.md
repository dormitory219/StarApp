## 1. 一句话结论

星目标不是普通待办/打卡工具，而是一个面向 3-12 岁儿童家庭的“亲子目标管理 + 积分激励 + 心愿兑换 + 儿童模式 + 宠物陪伴”的成长管理 App。它的核心价值是把家长想推动的学习、生活习惯和兴趣培养，转译成孩子能理解、愿意参与的星星积分、心愿奖励、宠物成长和成就勋章。

如果要复刻，第一版不应只做任务打卡，而应优先复刻这条闭环：

创建孩子档案 -> 配置目标/任务 -> 每日评分式打卡 -> 获得星星/积分 -> 兑换心愿/奖励 -> 数据反馈和成就激励。

## 4. 产品定位

### 4.1 目标用户

星目标的实际使用者分为两类：

| 用户 | 核心诉求 |
| --- | --- |
| 家长/监护人 | 制定孩子学习和生活目标，降低反复催促成本，用可量化方式管理行为变化 |
| 儿童 | 通过星星、宠物、心愿、勋章获得即时反馈，把“完成任务”变成有趣、有奖励的游戏化体验 |

官方描述强调“3-12 岁儿童”“宝贝”“家长轻松”“专注力、好习惯、终结拖延症”，说明它更接近儿童家庭管理工具，而不是成人自律工具。

| 儿童自主 | 开启儿童模式后，允许孩子自己打卡或查看进度 |
| 激励兑换 | 用星星/积分兑换心愿、奖励、特权 |

## 5. 功能模块拆解

### 5.1 孩子档案与多孩管理

已确认能力：

- 支持多孩添加。
- 支持选择宝贝。
- 每个孩子可以有独立任务、目标、心愿、积分与进度。

复刻要点：

- 孩子档案字段至少包括：昵称、头像、年龄/生日、性别可选、当前星星余额、累计星星、当前等级。
- 所有任务、心愿、宠物、勋章、统计数据都应绑定 child_id。
- 首页需要有清晰的孩子切换入口。

### 5.2 目标/任务系统

官方强调：

- 500+ 学习目标选择自定义。
- 200+ 生活习惯培养路径。
- 200+ 兴趣爱好。
- 目标库截图显示存在分类目标模板。
- 创建目标截图显示应支持重复、计时等设置。

推断的目标字段：

| 字段 | 说明 |
| --- | --- |
| 目标名称 | 如“每天阅读 20 分钟” |
| 分类 | 学习、生活、兴趣、家务、健康等 |
| 图标/插图 | 当前版本新增目标默认插图 |
| 星星奖励 | 完成后获得多少星星 |
| 惩罚/扣分 | 未完成或表现差时扣星，可选 |
| 频率 | 每日、每周、自定义日期 |
| 次数限制 | 当前版本支持周/月限制 |
| 是否计时 | 是否绑定番茄钟或时长 |
| 是否评分 | 支持评分式打卡 |
| 生效模式 | 日常、假期、自定义计划 |

### 5.3 评分式打卡

这是星目标区别于普通打卡 App 的重要点。官方称“星目标特有的评分式打卡，轻松打分，专为小朋友而设计”。

可能的机制：

- 不是简单完成/未完成，而是家长按表现给分。
- 评分映射到星星数量，例如满分得全部星星，低分得部分星星。
- 可以有原因备注或快捷原因。当前版本提到“自定义奖惩升级，新增快捷入口和原因记忆”。
- 打卡次数支持周/月限制，避免同一任务无限刷分。

复刻建议：

- MVP 先支持三档评分：很好、完成、需努力。
- 每档对应不同积分倍率：100%、70%、0 或扣分。
- 后续扩展 1-5 星评分、文字原因、图片/语音证明。

### 5.4 积分/星星系统

用户评论多次提到“星星”和“积分激励”。产品核心不是任务本身，而是星星作为家庭内部激励货币。

关键规则：

- 完成目标获得星星。
- 自定义奖励/惩罚可以增加或扣除星星。
- 星星用于兑换心愿。
- 累计星星可驱动等级、宠物粮、勋章等长期激励。

需要区分两套数值：

| 数值 | 用途 |
| --- | --- |
| 当前可用星星 | 兑换心愿时消耗 |
| 累计获得星星 | 统计成长、等级、勋章，不应因兑换减少 |

### 5.5 心愿库与兑换

官方强调：

- 300+ 心愿实现。
- 分阶段分方式奖励孩子成果。
- 心愿兑换新增动效并支持一键兑现。
- 心愿库截图显示存在心愿分类，如特权、成长等。

功能拆解：

| 功能 | 说明 |
| --- | --- |
| 心愿模板库 | 预置常见奖励，如玩具、亲子活动、零食、屏幕时间、外出游玩 |
| 自定义心愿 | 家长创建家庭专属奖励 |
| 心愿价格 | 使用星星定价 |
| 心愿状态 | 可兑换、已兑换、已兑现、过期/取消 |
| 一键兑现 | 家长确认奖励已经履约 |
| 兑换动效 | 强化孩子的成就感 |

复刻时要注意：心愿不是简单商品列表，而是亲子承诺管理。兑换后必须有“待兑现/已兑现”的状态，否则孩子会觉得奖励不可信。

### 5.6 儿童模式

官方描述：

- 家长端可在线开启儿童模式。
- 权限灵活设置。
- 儿童友好功能，轻松把控屏幕。
- 截图标题对应“儿童模式设置”。

可能权限：

- 是否允许孩子自己打卡评分。
- 是否允许孩子兑换心愿。
- 是否允许孩子查看全部心愿。
- 是否允许孩子使用番茄钟。
- 是否隐藏家长设置/会员/数据导出等入口。

复刻建议：

- 家长模式和儿童模式必须在交互上明显分离。
- 儿童模式要尽量少文字、多图形、大按钮。
- 家长设置区需要 PIN/验证，避免孩子修改积分规则。

### 5.7 家庭成员共享与多角色

官方确认：

- 支持家庭成员共享。
- 爸爸、妈妈、爷爷奶奶都可以为宝贝评分。
- 支持多角色管理共享。
- 支持学习机等多个平台数据云端共享。

角色建议：

| 角色 | 权限 |
| --- | --- |
| 创建者/主家长 | 所有权限，管理成员和会员 |
| 家长成员 | 创建目标、评分、兑换确认、查看统计 |
| 长辈成员 | 评分、查看今日任务、简单奖惩 |
| 儿童 | 儿童模式权限内操作 |

协作重点是“低学习成本”。评论中提到老人和孩子可以共享主账户自己完成打分，这说明产品在弱化复杂账号体系。

### 5.8 番茄钟/专注计时

官方确认：

- 支持一键开启倒计时、正计时。
- 当前版本支持悬浮按钮和后台持续计时。
- 用户曾反馈希望增加正计时，后续版本已经覆盖。

功能拆解：

- 倒计时：适合阅读 20 分钟、练琴 30 分钟。
- 正计时：适合记录实际学习/练习时长。
- 可绑定目标：计时完成后触发打卡或加星。
- 后台持续计时：避免切出 App 后中断。
- 悬浮按钮：快速暂停/继续/完成。

### 5.9 数据统计与导出

官方确认：

- 多维度数据统计分析。
- 成长打卡数据一键导出。
- 首页进度卡片支持置顶。
- 截图中有统计页面。

统计维度建议：

| 维度 | 指标 |
| --- | --- |
| 日维度 | 今日完成数、获得星星、未完成任务 |
| 周/月维度 | 完成率、连续打卡、星星趋势 |
| 分类维度 | 学习、生活、兴趣各自表现 |
| 目标维度 | 单个目标完成次数、平均评分 |
| 激励维度 | 心愿兑换次数、兑现率 |
| 成长轨迹 | 勋章、等级、累计星星 |

导出格式可先做 CSV，后续支持 PDF 成长报告。

### 5.10 宠物系统

官方确认：

- 内置多款电子宠物。
- 孩子通过坚持打卡获得宠物粮。
- 喂养宠物可解锁宠物成长等级。
- 当前版本新增等级形象、悬浮窗和自助恢复。
- 即将上线更多电子宠物。

产品作用：

- 把“坚持”从抽象结果变成可见陪伴。
- 让孩子短期内有比“兑换大心愿”更频繁的反馈。
- 形成情感绑定，提升留存。

复刻建议：

- MVP 可以先做一个宠物。
- 规则简单化：每日完成任务 -> 获得食物 -> 喂养 -> 经验增加 -> 升级换形象。
- 不建议第一版做复杂宠物状态，否则开发成本很高。

### 5.11 成就勋章

官方确认：

- 勋章体系覆盖坚持、专注、挑战等成长轨迹。
- 每一次进步会被记录与表彰。
- 截图资源包括“勋章”界面。

可复刻勋章类型：

| 类型 | 示例 |
| --- | --- |
| 连续坚持 | 连续 7 天阅读 |
| 累计完成 | 完成 100 次任务 |
| 专注时长 | 累计专注 10 小时 |
| 分类成长 | 生活习惯达人、阅读小达人 |
| 兑换成就 | 第一次兑换心愿 |
| 家庭协作 | 全家共同评分 30 次 |

### 5.12 假期模式/计划模式

官方确认：

- 寒暑假、小长假与日常评分互不干扰。
- 支持自定义计划模式。

复刻意义：

- 儿童任务高度受学校日程影响。
- 假期目标和日常目标不同，例如寒假阅读、旅行计划、作息调整。

MVP 可先支持：

- 日常计划。
- 假期计划。
- 计划生效日期范围。

### 5.13 错题本与 AI 模板

当前版本 1.8.6 新增：

- 错题本小应用。
- 模板库接入 AI，支持智能模板一键应用。
- 即将上线听写功能。

这表明星目标正在从“习惯打卡”扩展到“儿童学习工具集合”。不过复刻第一版不建议立即做错题本、AI 模板和听写，除非你的目标市场明确是学习机/学习管理。

## 8. 用户评论洞察

### 8.1 正向反馈

高频正向词：

- 孩子喜欢。
- 积极性提升。
- 主动读绘本、背古诗、练琴、写作业。
- 界面可爱。
- 计划设置灵活。
- 数据清晰。
- 多端同步。
- 无广告和干扰信息。
- 老人和孩子也能操作。

典型结论：

- 游戏化激励有效。
- 星星和心愿对儿童有真实驱动力。
- 家长愿意为“省心”和“可见进步”付费。

### 8.2 负向反馈

高频问题：

- 会员价格贵。
- 免费版限制明显，例如有评论提到一天只能打 5 个。
- 闪退、打不开、登录/加载失败。
- 同步或刷新不及时。
- 自定义自由度不够，例如不能设置小数。

复刻时要特别注意：

- 稳定性和同步速度会直接影响信任。
- 如果商业化过早或限制太硬，容易被家长反感。
- 儿童产品的奖励兑现和积分准确性必须可靠，一旦错乱会严重破坏使用体验。

| 目标 | 目标库、我的目标、创建目标、计划模式 |
| 心愿 | 心愿库、可兑换心愿、待兑现心愿、历史记录 |
| 成长 | 数据统计、勋章、宠物、等级 |
| 家庭 | 儿童模式、成员共享、孩子档案、导出、设置 |

儿童模式下建议简化为 3 个主入口：

| 入口 | 内容 |
| --- | --- |
| 今天 | 今日任务、打卡、番茄钟 |
| 我的星星 | 星星余额、可兑换心愿 |
| 我的成长 | 宠物、勋章、等级 |

## 10. 关键业务流程

### 10.1 家长首次使用

1. 注册/登录。
2. 创建家庭。
3. 添加孩子档案。
4. 从目标库选择模板或自定义目标。
5. 设置奖励星星、频率、评分规则。
6. 添加心愿或从心愿库选择。
7. 开始每日打卡。

### 10.2 每日打卡

1. 进入首页。
2. 选择孩子。
3. 查看今日任务。
4. 对单个任务评分。
5. 系统计算星星。
6. 展示获得星星动效。
7. 更新今日进度、统计、宠物食物、勋章条件。

### 10.3 心愿兑换

1. 孩子查看可兑换心愿。
2. 选择心愿。
3. 系统判断星星余额。
4. 扣除星星，生成兑换记录。
5. 心愿进入待兑现。
6. 家长一键兑现。
7. 记录兑现时间，触发成就或反馈。

### 10.4 儿童模式

1. 家长开启儿童模式。
2. 配置权限。
3. 孩子只能看到允许的功能。
4. 敏感操作需要家长 PIN。

## 12. 复刻 MVP 范围

### 12.1 第一版必须做

| 模块 | 必做能力 |
| --- | --- |
| 家庭/孩子 | 创建家庭、添加孩子、孩子切换 |
| 目标 | 创建目标、目标模板、重复规则、星星奖励 |
| 打卡 | 今日任务、评分式打卡、星星结算 |

| 儿童模式 | 简化界面、权限控制、家长 PIN |
| 数据 | 今日/本周完成率、星星趋势 |

### 12.2 第一版可以延后

| 模块 | 延后原因 |
| --- | --- |
| AI 模板 | 可先用人工模板库替代 |
| 错题本 | 属于学习工具扩展，不是核心闭环 |
| 听写 | 同上 |
| 多宠物 | 一个宠物即可验证留存 |
| 复杂勋章体系 | 可先做 6-10 个基础勋章 |
| 数据导出 PDF | 可先做 CSV 或简易报告 |
| 学习机多端 | 技术和渠道成本较高 |

### 12.3 推荐 MVP 用户故事

- 作为家长，我可以给孩子创建每天阅读、练琴、整理书包等目标。
- 作为家长，我可以按孩子表现给不同评分，而不是只能点完成。
- 作为孩子，我完成任务后能立即看到星星增加。
- 作为孩子，我可以用星星兑换心愿。
- 作为家长，我可以确认心愿已经兑现。
- 作为孩子，我可以喂养一个宠物并看到它升级。
- 作为家长，我可以看到孩子本周完成率和星星变化。

## 13. 商业化观察

评论显示星目标存在会员机制，且用户对价格敏感。至少有用户反馈：

- “要会员”。
- “会员太贵”。
- “一天只能打 5 个，超过 5 个就要收费”。

复刻版商业化建议：

| 免费版 | 付费版 |
| --- | --- |
| 1 个孩子 | 多孩管理 |
| 每日有限打卡数 | 无限目标/打卡 |
| 基础心愿 | 高级心愿模板 |
| 基础统计 | 高级数据报告/导出 |
| 1 个宠物 | 多宠物/皮肤 |
| 少量勋章 | 完整成就系统 |

要避免第一天就让用户配置很多目标后才发现不能使用。更好的策略是在创建前清晰提示限制，或给 7 天完整试用。

## 14. 竞争壁垒与可超越点

星目标当前优势：

- 儿童家庭场景明确。
- 目标、打卡、积分、心愿、宠物、勋章形成闭环。
- 模板数量多，家长启动成本低。
- 多角色和儿童模式贴近真实家庭使用。

可超越点：

- 更稳定的离线/弱网体验。
- 更透明、温和的免费限制。
- 更好的心愿兑现仪式和亲子反馈。
- 更细的儿童年龄分层，例如幼儿、小学低年级、小学高年级。
- 更强的家庭协作：长辈快捷评分、老师/托管角色。
- 更清楚的积分规则解释，减少孩子和家长争议。
- 更好的数据报告：不只是完成率，而是行为变化建议。

## 15. 设计风格推断

从截图和用户评论推断：

- 视觉偏可爱、明亮、儿童友好。
- 大量使用星星、插图、宠物、卡片、动效。
- 家长端仍要保持清晰高效，不应过度幼稚。
- 儿童端要图形化、大按钮、少配置。

复刻建议采用“双层视觉”：

- 家长端：清晰、轻量、可扫描，强调效率。
- 儿童端：更游戏化，强调星星、宠物、奖励反馈。

## 16. 风险与待验证项

需要后续通过实机体验或更多截图验证：

- 评分式打卡的具体评分档位。
- 免费版和会员版的准确限制。
- 儿童模式具体权限项。
- 心愿兑换是否需要家长审批。
- 宠物系统是否有饥饿、恢复、等级形象等完整状态。
- 勋章界面的具体分类和触发条件。
- 数据导出的格式和内容。
- 学习机/多平台的具体形态。

## 17. 后续复刻建议

建议下一步产出三份工程前置文档：

1. PRD：明确 MVP 范围、页面结构、用户故事和验收标准。
2. 数据库设计：围绕家庭、孩子、目标、打卡、星星流水、心愿兑换建模。
3. 原型稿：先画家长首页、儿童今日任务、目标创建、心愿兑换、宠物页 5 个核心页面。

最小可行产品的本质不是“做一个打卡 App”，而是做一个孩子愿意每天打开、家长愿意持续维护的亲子激励系统。星目标真正值得复刻的是这个激励闭环。
